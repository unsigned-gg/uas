Planner: `uas-planner`, 2026-10-10. Every path below was read in a worktree cut from that base.
Tiers: `verified` = I ran or read it at the path named; `reported` = the spec says it; `asserted` = my judgement.

## Findings the builders must know

1. **Spec 0036 is not built, and nothing here needs it [verified]:** `grep -rn 'HostSlotArbiter\|slot-.*\.lock\|try_lock' crates --include=*.rs` prints nothing. Spec 0040 locks the marker file with `File::try_lock` directly (D1). It never touches the host slot locks. Every package below can land before 0036's arbiter. The overlap is textual only: both specs add fields to `PoolConfig`, variants to `PoolError` and code to `crates/uas-pool/src/slot.rs`, so whichever lands second rebases. After 0036 lands, `SlotPool::allocate` (spec wording) will exist; today the calls are `create_slot`, `warm_slot` and `acquire_lease` [verified: `slot.rs` lines 129, 158, 172], and there is no `allocate`.
2. **`SlotPool` never calls `WarmWorktree` [verified]:** `grep -rn WarmWorktree crates --include=*.rs` outside `worktree.rs` hits only `lib.rs` and `tests/gitoxide.rs`. The pool holds a `WorktreeRef` and a `Freezer`. The cgroup is created by `create_slot` through `CgroupFreezer::new` (`slot.rs` line 141, `freezer.rs` lines 159-168). The worktree is created by whoever calls `WarmWorktree::provision`. So REQ-0040-12 (marker before the cgroup) has no code site yet, and REQ-0040-05 (kill a cgroup with no marker) would kill the cgroup of a live pool that used `create_slot` with a `cgroup_base` and no provisioned worktree. See P7 (BLOCKED). Until P7 lands, no production caller may set the cgroup root of reconcile. P5's tests set it; the default is off.
3. **`SlotPool::new` is infallible and called from 11 sites [verified: `grep -c SlotPool::new`]:** `benches/slot_lifecycle.rs` (3), `tests/lifecycle.rs` (7), `tests/launch.rs` (1). Three of those build `PoolConfig { max_slots, idle_suspend_duration, cgroup_base }` with all fields and no `..Default::default()` (`tests/lifecycle.rs` lines 36 and 169, `tests/launch.rs` line 297). Adding a field to `PoolConfig` breaks them, so P4 edits those three literals. D4 says a failed reclaim never stops the pool, so `new` stays infallible: P4 stores the `ReconcileReport` on the pool and exposes it through an accessor. Reconcile runs only when the new config field is `Some`, which keeps every existing caller unchanged.
4. **`PoolError::ReconcileRefused` is an internal per-entry result, not a constructor failure (asserted):** D6 and REQ-0040-08 say skip, log at `warn`, remove nothing. D4 says the pool starts anyway. So the variant is returned by the per-entry scan step, logged by the caller and counted. Whether a refused entry counts in `failed` is not in the spec. P4 counts it in `failed` so the operator sees it (OPEN).
5. **`WarmWorktree::provision` creates the branch ref before the control directory [verified: `worktree.rs` lines 62-82].** D3 deletes the branch by reading the marker, so a crash between the ref and the marker leaks a branch nobody can find. P3 moves the branch creation after the marker rename. `common_dir()` is available before the reference is made.
6. **The marker `cgroup` field has no source in `provision` [verified: signature at `worktree.rs` line 45 takes no cgroup].** P3 keeps the signature, because five call sites in `tests/gitoxide.rs` use it, and writes the relative name `slot-<slot_id>` (spec 0015 D3 names it). Reconcile derives the real path from `cgroup_base` plus that name (asserted).
7. **`make ebpf-test` cannot carry the live cgroup test [verified]:** the recipe (`Makefile` lines 87-90) runs only the `uas-ebpf` binary `live_probes`. CI (`.github/workflows/ci.yml`, step "live probes") fails on any `skipped:` line except the unshare one, and fails unless the log has `9 passed`. The CI pod holds only BPF and PERFMON capabilities [reported: spec 0005 lines 30-40], so it probably cannot create `/sys/fs/cgroup/uas` [asserted, not probed], and a skipping test would turn that job red [verified: the `ci.yml` filter]. The spec's Test paragraph ("run under `make ebpf-test`") therefore conflicts with spec 0005. P8 holds the Makefile hook (BLOCKED). The builder's proof does not need it, see finding 8.
8. **A workstation proof needs no sudo on ceres [verified 2026-10-10 as uid 1000]:** the process cgroup (`/proc/self/cgroup`, resolved to `/sys/fs/cgroup/user.slice/.../herdr-estate.service`) is writable, a child directory there gets `cgroup.kill` and `cgroup.events`, and `mkdir` plus `rmdir` succeeded. `PoolConfig::cgroup_base` is configurable, so the live test uses a child of `current_process_cgroup_path()` as the base. This also satisfies the `verify_safety` rule in `freezer.rs` line 186 (a slot cgroup must be a strict child of the base and not the process's own cgroup).
9. **A scanned cgroup can be the process's own ancestor [asserted from `freezer.rs` `verify_safety`, line 186 onward]:** writing `1` to `cgroup.kill` of an ancestor kills the pool and the test runner. P5 refuses a slot cgroup that equals or contains the current process cgroup, and logs it as `ReconcileRefused`.
10. **Replayed sessions get a `NoopCompensator` and no way to change it [verified: `workflow.rs` `replay_from_events` builds `WorkflowSession::new`, the `compensator` field is private].** The spec's engine test replays an activity and expects a compensator to run, so P6 adds a way to attach one to a replayed session.
11. **The engine holds lease ids only [verified]:** `grep -n 'LeaseNotFound' crates/uas-engine -r` prints nothing, `uas-engine/Cargo.toml` has no `uas-pool` edge, and `WorkflowSession::start` takes a `LeaseId`. There is no lease-acquiring port in the engine. REQ-0040-10 says "re-admit the task through a fresh lease". P6 returns a `Readmit` disposition and compensates; acquiring the fresh lease stays with the caller. Done-when row 5 of the spec checks only the compensator, so this is within the Test table (OPEN).
12. **`uas-pool` lacks `serde_json` [verified: `crates/uas-pool/Cargo.toml`].** The marker is JSON. It is a workspace dependency already used by six crates, so P3 adds one `serde_json = { workspace = true }` line and no new external crate. Spec 0004 has no row for `serde_json` [verified: `grep -n serde_json specs/0004-*.md` prints nothing], so `pin-check` skips it and no amendment is needed.
13. **`File::try_lock` conflicts across open file descriptions in one process [verified: a Python probe opened one file twice, took `flock(LOCK_EX|LOCK_NB)` on the first, and the second printed `blocked`].** A same-process second `open` of the marker conflicts, so unit tests can hold a "live owner" without a child. The spec's table still wants child-process fixtures for REQ-0040-03, 04 and 12, so those use `std::env::current_exe()` helpers in the pattern of `crates/uas-sandbox/tests/netns.rs` line 63 (`probe_command`).
14. **The rename in D1 can clobber a live marker (a gap in D1, asserted from POSIX `rename` semantics).** A plain `rename` of `.tmp` over an existing `uas-pool.json` replaces it silently. A reconciler holding the lock on the old, now-unlinked inode would then reclaim the control directory that holds the new live marker. This gets likely once spec 0036 frees host slot ids on death and another process reuses a slot id. P3 renames with `rustix::fs::renameat_with` and `RenameFlags::NOREPLACE` (the `fs` feature is approved, spec 0004 line 176), so a leftover marker fails `provision`. P4 compares the locked descriptor's device and inode with a fresh `symlink_metadata` of the marker path and treats a mismatch as `kept`.
15. **Legacy leftovers are out of reach (OPEN):** a worktree control directory or cgroup left by a pool from before this spec has no marker. D2 scans markers, and REQ-0040-05 covers only cgroups. A control directory with no marker is never reclaimed.

## Cgroup proof, in one place

CI proves, without cgroups: the scan, the lock probe, ordering of the file steps, the path and symlink refusals, the timeout, and deepest-first removal (P4, P5 temp-dir tests). Only a real cgroup proves that `cgroup.kill` kills a populated subtree and that `populated 0` appears. P5's live case proves it on ceres as uid 1000, and the builder pastes the run. The same case skips with a printed line on a runner without a writable cgroup. P8 decides whether CI ever runs it.
