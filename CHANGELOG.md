## [Unreleased]

### Changed
- Landing receipts record `development_head` on a stale base, and a human raise (`HumanRaise`) may lift the evaluator cap, but never above the verify gate (spec 0022 D9, D10). `LandingReceipt::new` now returns a `Result`.
- Workspace `rust-version` raised to 1.89: the pinned `agent-client-protocol` 2.2.0 (via uuid 1.28) needs it, and aya already needed 1.87 (spec 0004, lane decision 2026-10-10).

### Added
- `cas-router` prefix hashing and affinity choice (spec 0017 D1-D3, CER-2729, CER-2730): `PrefixInput::hash` takes the first 16 bytes of the SHA-256 of a canonical, tool-sorted prefix; `AffinityTable::choose` picks the healthy replica with the highest rendezvous weight and `ranked` lists the fallback order. No network, no multiplexer, no health probe yet.
- Spec 0024 and Estate Saga CPM with Agent Sprint Wave Strategy (CER-2738): `cas-engine` adds DAG cycle detection, forward/backward Critical Path Method schedule calculation (`CpmSchedule`), slack extraction, and agent sprint wave partitioning (`WavePlan`, `WaveCoordinator`) with estate-bounded concurrency (default 3), role/model/workspace classification, verdict line limit verification, and compensator rollback; `cas-cli` adds `--show-cpm` and `--wave` execution flags.
- cas-pool: Gitoxide (gix) in-process worktree provisioning and teardown (CER-2724). Provisions ephemeral worktrees directly via gix without external git CLI processes. Eliminates lock collisions on .git/config via shared ODB references. Resets worktrees to clean commit state in sub-second time. Prunes worktree directories and branch references cleanly on teardown.
- `cas-acp` serves `initialize`, `session/new` and the `session/cancel` notification over stdio (spec 0016 A1, CER-2683): `session/new` takes a slot from the pool port and starts a `cas-engine` session; `session/cancel` freezes the slot, then releases it; the error codes are -32700, -32600, -32601, -32602, -32001 and -32002. No turn runs yet.
- `cas-acp` serves `initialize`, `session/new` and the `session/cancel` notification over stdio (spec 0016 A1, CER-2683): `session/new` takes a slot from the pool port and starts a `cas-engine` session; `session/cancel` freezes the slot, then releases it; the error codes are -32700, -32600, -32601, -32602, -32001, -32002 (lease) and -32603 (internal). Requests without an id, or with a bad jsonrpc, get -32600 before any side effect. No turn runs yet.
- Live eBPF gate job `ebpf-live` on the ci-kernel runner: rebuilds `cas-ebpf.o` with the pinned dated nightly and bpf-linker 0.11.1, fails on drift, runs the live probes as uid 0, and fails on any skipped live case except the nested unshare skip (spec 0005 D1).
- Landing receipt and activity (spec 0022 D1-D3; spec 0023 D3 partial, the evaluator cap only): `cas-domain::LandingReceipt` gives `verified` only when `blackwall.toml` sets a verify command, reconcile exits zero and no evaluator file changed; `cas-engine::LandingActivity` checks the base, runs `blackwall reconcile` and `blackwall pr`, refuses a stale base, and opens no PR after a failed reconcile or when `blackwall.toml` has no verify command.
- Spec 0014 amendment: document PID namespace resolution, Fact T13, Decision D11, two-phase promotion rules, the six-map architecture table, and ExecEvent ns_pid layout (CER-2719, CER-2720).
- cas-ebpf resolves pid namespaces (CER-2719, CER-2720): the daemon records its `/proc/self/ns/pid` in a `PIDNS_CONFIG` map and the probes translate `current` with `bpf_get_ns_current_pid_tgid`; a `track` request is promoted at the process's next fork or exec; `ExecEvent` slot 164 is now `ns_pid`. Found by the first sudo `make ebpf-test` on ceres (4 of 8 failed under systemd's pid namespace); the second run passed 8 of 8 (2026-10-10).
- Repo subagents under `.claude/agents/` (cas-builder and cas-ebpf-builder on haiku, cas-critic and cas-engineer on opus, cas-foreman on sonnet) with a README, and a saga team `cas-cockpit` in `.saga/teams.toml` whose personas are those files. Models follow the operator's rule of 2026-10-10; the global builder and pr-reviewer assume `origin/main` and are replaced here.
- cas-pool and cas-ebpf: default slot CPU quota to two CPUs (200,000us quota / 100,000us period) per Spec 0020 D3; record CpuCap in CgroupFreezer and AuditReceipt.cpu_cap; warn on missing cpu.max controller without failing slot launch; add Criterion slot lifecycle micro-benchmark measuring sub-microsecond slot operations (Spec 0015, Spec 0019, Spec 0020).
- Spec 0021 (`cas-storage` scope and phase): assigns `cas-storage` to Phase 6 (Distributed Storage & Operator Client) alongside the `ais-k8s` operator deployment, resolving open gaps 3 and 4 in spec 0001; defines protocol boundaries for rustfs (S3 WORM via `aws-sdk-s3`), aistore (HTTP REST and S3 streaming gateway), and minikv (HTTP/REST Raft metadata consensus).
- cas-pool: cgroup v2 freezer and controller with slot allocation state machine (CER-2722, CER-2723). Provisions child cgroup `slot-<id>` under delegated base. Enforces safety invariants against freezing the process cgroup. Configures `cpu.max` and `memory.high`/`memory.max` limits. Manages `Thawed` and `Frozen` state transitions through `cgroup.freeze` with `cgroup.events` polling and POSIX `SIGSTOP`/`SIGCONT` fallback. Enforces host capacity ceiling (`max_slots = 2` on ceres) and spec 0007 lease lifecycle rules with auto-suspend and resume.
- Spec 0014 userspace and kernel probes (CER-2719, CER-2720): the `sched_process_exec`, `fork` and `exit` tracepoint programs fill `TRACKED_PIDS` and stream 168-byte `ExecEvent` records over a ring buffer; `cas-ebpf` adds the aya loader, `RunHash` transcript digest and receipt, `PRIO_PGRP` clamping through rustix (`clamp::enter_clamped_group` for `pre_exec`), a host probe, the `cas-ebpfd` socket daemon with its line protocol and blocking client, and `make ebpf-build` / `make ebpf-test`. `build.rs` refuses to compile when `ebpf/cas-ebpf.o` and its recorded sha256 disagree. Measured on ceres 2026-10-09 and re-proven by a test: `setpriority(PRIO_PROCESS)` clamps one thread, `PRIO_PGRP` clamps all; `cas-ebpfd` checks `SO_PEERCRED` on every request (own pids only, per-uid quota, own events only); the fork and exit tracepoint offsets in the first draft of spec 0014 were wrong and are corrected.
- LeanSpec EARS requirement conversion: standardized spec-driven development on Easy Approach to Requirements Syntax (Ubiquitous, Event-driven, State-driven, Unwanted behavior, Optional feature, Complex) across all 18 repository specs (0001 through 0018), spec template, and reference documentation.
- Specs 0014 through 0018: LeanSpecs defining eBPF priority clamping and audit telemetry (`cas-ebpf`), slot pool with cgroup freezer and gitoxide worktrees (`cas-pool`), Zed Agent Communication Protocol server (`cas-acp`), FastCache prefix hashing and affinity routing (`cas-router`), and MAD stack operator deck with settle queue (`cas-deck`). Kernel-side eBPF bytecode subcrate and committed object staged at `crates/cas-ebpf/ebpf/`.
- Spec 0013 and the gateway socket proxy (CER-2718): `cas-sandbox::ipc` owns `<workspace>/.ipc/llm.sock`; `cas-router::uds_proxy` serves it on tokio, allows only the gateway paths, replaces the worker's `Authorization` with the key from a file the worker cannot read, and forwards over plain HTTP to the tailnet or in-cluster gateway. The escape suite measures that a jailed worker can connect to a pathname socket outside its workspace, so the allowlist is the boundary.
- Spec 0012 and the `cas-sandbox` escape suite (CER-2684, CER-2721): one jailed worker runs the attack matrix (writes and links out of the workspace, execute from `/tmp`, `no_new_privs` and Landlock across exec, setuid `sudo`, TCP, UDP and raw-socket egress) and the gate asserts every row.
- Spec 0011 and `cas-sandbox::netns` (CER-2717): `isolate()` installs a `pre_exec` hook that gives the worker a private network namespace with only `lo` up, through `unshare(CLONE_NEWNET)` or, unprivileged, a user namespace with an identity uid/gid map; `rustix` 1.1.5 enters the workspace.
- `cas-sandbox` launcher (CER-2716): `jail()` installs a `pre_exec` hook that enters the Landlock ruleset with `PR_SET_NO_NEW_PRIVS` before `exec`, `launch()` spawns a worker inside it, and a child that cannot enter the jail never runs (`SandboxError::JailRefused`).
- `cas-engine`: `MeshIntent` and optional `intent`/`hop_count` fields on `CortexMeshEvent` mirror the cortex mesh envelope contract (CER-2737). `CortexMeshEvent::increment_hop` enforces the bounded-recursion rule: at most 10 agent-to-agent hops, then an error demanding human escalation. The JSON wire form matches `cortex-domain` `MessageIntent` (snake_case, absent distinct from defaulted).
- Spec 0010 and the first `cas-sandbox` code (CER-2715): `probe()` reports the kernel Landlock ABI, `LandlockRulesetBuilder` canonicalises paths and builds the default-deny worker ruleset, and the `landlock` 0.4.7 dependency enters the workspace under the spec 0004 ruling of 2026-10-09.
- Record the CER-2671 custody rollout artifacts: the `spec-0001-deltadb-custody` task (the run that landed in PR #21) and the `estate-custody-rollout` saga flow (terrain assert, custody verify, jailed run, settle, reconcile gate, PR landing on green).
- Saga compensation runner, replay durability, and vendored contracts (CER-2677, CER-2678, CER-2679): `cas-engine` adds backward saga compensators (`WorktreeCleanupCompensator`, `BranchPruneCompensator`, `LeaseReturnCompensator`, `CompositeCompensator`), event log replay, and flow execution; `cas-cli` adds headless flow runner `cas harness run --flow <path>`; vendored domain schemas, protobufs, and flow templates from Soma, Cortex, and Saga under `vendor/`.
- Spec 0008 and service edge integration modules connecting CAS Substrate to estate pillars (CER-2676): `cas-domain` adds `PolicyTier` and `SomaClassification`; `cas-engine` adds `SomaAdmissionGate`, `ReverieClient`, `CortexMeshEvent`, `SettleCard` and `SettleQueue`, and `SagaFlowCoordinator` with backward rollback; `cas-cli` adds `--policy-tier` admission checking.
- Blackwall custody setup (CER-2671): `blackwall.toml` (claude provider, `make check` and `make hygiene` as the verify gate, PRs into `development`, automerge off), the `tasks/` library with the first task `harness-evidence`, the `custody-run` skill, `make custody-check`, and `.blackwall/` ignored.
- `cas-engine` workflow sessions, activities, and event log with `cas harness` CLI runner and `.saga/flows/cas-builder.toml` dogfood flow.
- Spec 0007, the lease rules: one live lease per slot, only the lease token renews a lease, a renewal extends by at least one second, and a draining slot keeps its worktree. `cas-domain` adds `check_slot_free`, `Lease::holds_slot_at`, `LeaseToken::matches`, and the errors `SlotLeased` and `TokenMismatch`.

### Changed
- Specs 0014 and 0015: tightened spec 0014 below 300 lines with zero warnings while maintaining all facts, format offsets, peer rules (per-UID track quota of 256 PIDs), and counter slots (`DROPPED_EVENTS[0]` reserve failures, `DROPPED_EVENTS[1]` refused fork inserts); integrated eBPF priority clamping and audit hooks (`pre_exec` `enter_clamped_group`, `DaemonClient::track`, `EventStream`, `AuditReceipt`, and `unattested` fallback) into spec 0015 for `cas-pool`.
- Adopt DeltaDB and Blackwall custody process with PR-floor constraints in spec 0001 (CER-2671).
- `Lease::renew` and `LeaseLedger::renew` take the lease token as a new parameter. A renewal by zero seconds now fails. The in-memory ledger refuses a second live lease on a slot.
- `release-plz`: name GitHub releases `v{{ version }}` to match tag names instead of `cas-cli-v{{ version }}`.
- `ci`: drop the dead `release` trigger and attach job from `sbom.yml`, generating the SBOM artifact on push to `main` only.
- `cas-sandbox`, `cas-pool` and `cas-ebpf` deny `unsafe` instead of forbidding it. A block opts in with `#[allow(unsafe_code)]` and a `// SAFETY:` comment, which clippy enforces. Spec 0001 and spec 0004 record this ruling, the BPF program licence (`Dual MIT/GPL`, program object only) and the sudo `make ebpf-test` decision.

### Fixed
- `cas-cli`: `cas harness run` makes `--evidence` optional, defaults dry runs to heuristic evidence, and rejects claiming verified or reported evidence when simulating execution (CER-2671).
- `cas-domain`: deserializing a `Slot`, `Lease`, `Budget` or `Envelope` now runs the same checks as the constructors. Before, JSON could build a `Leased` slot with no worktree, a lease that ends before it begins, a zero budget, or an envelope with a bad id.
- `cas-ebpf`: a tracked worker that runs `unshare -Upf --fork` is no longer lost to the audit. When the namespace helper fails, the probes fall back to the global tgid with `ns_pid` 0, so the nested task stays in `TRACKED_PIDS`, its exec is audited, its children are tracked and its exit evicts it. `cas-ebpfd` never re-clamps `ns_pid` 0, refuses `track` and `untrack` of pid 0, and refuses any peer, root included, whose pid namespace differs from its own. Tests now use fixtures with `ns_pid` different from `pid`, and the exit test asserts on `TRACKED_PIDS` by global pid (CER-2773, spec 0014 D12).
- cas-ebpf reads the sched tracepoint field offsets from tracefs at load (spec 0014 D13, T16). Fork `child_pid` is at offset 20 on kernel 6.18, not 44, so the fork probe read the wrong bytes there. A format file that breaks the layout rules stops the load before any attach.
- `cas-ebpf` tracefs load refuses a `filename` field typed `__data_locx`. The check matches the exact `__data_loc` token (spec 0014 D13).

## [0.1.0] - 2026-10-08

### Added
- The repository, generated from `cerebral-work/rust-monorepo-template` (template `main` at `1366ed9`) and renamed with `make new-repo NAME=cas`: the crates `cas-domain` and `cas-cli`, the `xtask`, the gate targets, CI, moon, lefthook, the specs and the agent files.
- Eight placeholder crates from the research design: `cas-engine`, `cas-pool`, `cas-sandbox`, `cas-ebpf`, `cas-router`, `cas-acp`, `cas-storage` and `cas-deck`. Each compiles and has a README that names its research section, phase and open questions.
- Spec 0001 `cas-architecture-and-crate-layout` replaces the template architecture spec. It pins the nine research crates plus `cas-cli`, the downward dependency rule, the invariants, the failure matrix, the integration edges and the open gaps. Spec 0004 lists the evaluated dependencies and the two copyleft exclusions. README, AGENTS.md, the docs index and `engineering/` describe CAS.
- `cas-domain`: the slot state machine, leases with a `LeaseLedger` port, evidence tiers and envelopes, plus a `cas demo` that walks a slot through its lifecycle.

### Changed
- The promotion PR from `development` to `main` now merges on green CI, by operator ruling on 2026-10-08. AGENTS.md, CONTRIBUTING.md, the release skill and spec 0003 say so. Spec 0003 also names the real required check `rust / cargo`.

### Fixed
- The `release` workflow installs a pinned `gh` 2.101.0 before release-plz. Before this, every push to `main` failed with `gh: command not found`, and no tag or release was made. The release-plz step now runs only on `main`.
- The `release` job gets `pull-requests: read`. release-plz lists the pull requests of the released commit, and without this scope the call failed with 403 on `main`.
